# Production Demos

This directory contains production-ready demonstration scripts for the CLINC150 Intent Classification system. These scripts provide interactive web interfaces using Gradio for exploring the capabilities of the trained models.

## Available Demos

### 1. Intent Classifier Demo (`intent_classifier_demo.py`)

A comprehensive web interface for intent classification and semantic search.

**Features:**
- Select from multiple classification and RAG models
- Classify user utterances into intents
- View confidence scores and top predictions
- For RAG models: retrieve similar utterances from the training set
- Interactive model selection with descriptions

**Usage:**
```bash
python scripts/demos/intent_classifier_demo.py
```

**Models Supported:**
- Naive Bayes
- Linear SVM
- TF-IDF + SVM (bigrams)
- MiniLM + Logistic Regression
- RAG CentroidNN
- RAG k-Majority
- RAG LLM (Local embeddings)
- RAG LLM (OpenAI embeddings)

### 2. Intent Trend Analyzer (`intent_trend_analyzer.py`)

Analyze intent trends and evolution patterns using semantic search and LLM-powered analysis.

**Features:**
- Retrieve semantically similar utterances from the training set
- LLM-powered relevance classification
- Trend analysis comparing new utterances to historical patterns
- Interactive configuration

**Usage:**
```bash
python scripts/demos/intent_trend_analyzer.py
```

**Requirements:**
- FAISS index and metadata files (generated by the pipeline)
- LLM access (Ollama or OpenAI via litellm)

### 3. Semantic Search Demo (`semantic_search_demo.py`)

Simple semantic search interface for finding similar user utterances.

**Features:**
- Search for semantically similar utterances
- Adjustable number of results
- Display intent labels and similarity scores
- Configurable index and metadata paths

**Usage:**
```bash
python scripts/demos/semantic_search_demo.py
```

## Prerequisites

1. **Trained Models**: Run the complete training pipeline first:
   ```bash
   python scripts/pipeline/run_all.py
   ```

2. **Embeddings**: Ensure embeddings and FAISS indices are built (done automatically by the pipeline)

3. **Dependencies**: All required packages are in `pyproject.toml`. Install with:
   ```bash
   uv sync --extra demo
   ```

4. **LLM Access** (for trend analyzer):
   - For local models: Ensure Ollama is running and models are pulled
   - For OpenAI: Set `OPENAI_API_KEY` environment variable

## Configuration

All demos automatically load configuration from `config/config.yaml` to determine:
- Model directory paths
- Embedding directory paths
- Default model names
- LLM model settings

You can override paths in the Gradio interface if needed.

## Troubleshooting

### Models Not Found
- Ensure you've run the training pipeline: `python scripts/pipeline/run_all.py`
- Check that the model directory path in the demo matches your `config.yaml` settings
- Verify models exist in `output/{run_name}/models/`

### FAISS Index Not Found
- Run the embeddings pipeline step: `python scripts/pipeline/02_build_embeddings.py`
- Check that embeddings directory path matches your `config.yaml` settings
- Verify index files exist in `output/{run_name}/embeddings/sbert/` or `output/{run_name}/embeddings/openai/`

### LLM Errors (Trend Analyzer)
- For Ollama: Ensure `ollama serve` is running and models are pulled (e.g., `ollama pull llama3.1:8b`)
- For OpenAI: Set `OPENAI_API_KEY` environment variable
- Check that the LLM model name in `config.yaml` matches your available models

## Notes

- All demos use caching to avoid reloading models on every request
- Model loading errors are displayed clearly in the interface
- Paths can be customized in the Gradio interface if your setup differs from the defaults
